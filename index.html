Opening line: "Most of us use AI to get an answer. Hermes is interesting because we can give it a bounded job — and ask it to show the evidence." 45 seconds. Positioning: a practical evaluation, not a company-approved deployment.

The answer is only half the work.

  • Who has copied code from a chat window, run it, and pasted the error back?
  • That back-and-forth is the handoff tax.
  • An agent can do parts of that loop directly: read a file, run a test, inspect the result, revise.
  • We still set the goal, scope, and acceptance criteria.
60 seconds. Ask the room the opening question. The distinction: a configurable, persistent runtime we operate around our own workflows — not just a chat window with tools.

The interface keeps moving up the stack: completing keystrokes, to working inside the editor, to running in the background, to owning outcomes over days and months. Hermes sits at that third and fourth stage — a persistent worker you hand bounded jobs to, and check the evidence.

Hermes is the worker, not the model.

  • Model = the reasoning and language engine.
  • Hermes = the surrounding runtime: packages task + context, exposes tools, executes tool calls, returns results.
  • Tools do the actual work: reading files, browsing pages, running commands, calling integrations.
A model saying it changed something is not evidence the change happened. Verification remains essential.
75 seconds. Hermes is an open-source agent framework from Nous Research — not a new foundation model. Permissions come from the account and tools you give it.

Why run Hermes?

  • Configurable execution — local or remote backends
  • Model choice — pick the provider per task
  • Continuity — memory and skills across sessions
  • Many front ends — desktop app, CLI, messaging platforms
  • Open source — inspect it, extend it

No single feature is unique to Hermes. Evaluate the fit.

90 seconds. Operating it takes effort; memory can go stale; messaging needs explicit setup. Use only company-approved channels for work.

A good agent closes the loop.

  • Incident? Inspect logs and explain before remediating.
  • Code? Run the tests and report their actual output.
  • Record update? Read back the exact record.
Make the evidence requirement part of the task — e.g. "a pod in Running phase is not proof all containers are ready."
75 seconds. The important part is not acting — it's closing the loop with evidence you can check.

Useful experience becomes reusable context.

  • Memory — bounded, curated facts and history
  • Skills — instruction documents the agent loads when relevant; it can create or update them after learning a workflow
  • Session recall — retrieve past work on demand
A skill can preserve a mistake too — review important procedures. Don't save sensitive data in persistent memory.
75 seconds. Chats don't retrain the model's weights — "learning" here means saved procedures and context.

Use cases beyond writing code.

  • Nontechnical: source gathering, structured summaries, notes → actions
  • Developers: reproduction, tests, documentation, proposed changes
  • IT: start with read-only inspection in a lab
  • Scheduled digests — host must be running, credentials valid

Integrations need configured tools, APIs, or MCP servers — not magic.

90 seconds. These are candidate workflows, not promises that every integration is installed.

From request to reviewable deliverable.

  • A low-risk first workflow: inputs and outputs are visible.
  • Distinguish numbers it computed from recommendations it inferred.
  • Require citations (e.g. ticket IDs) so a teammate can audit each concern.
Don't let it send the brief or edit tickets without separate approval.
60 seconds. Before using at work: check whether the export can be sent to the selected model provider. An anonymized or synthetic dataset is a better starting point.

  • Home infrastructure: manages my K8s cluster and DNS, internal and public
  • Bounded jobs, with evidence required before I trust the result

Give it authority in layers.

  • Your local runtime is not automatically a private inference environment.
  • Prompts, documents, and tool outputs may go to the chosen provider.
  • Redaction and approval controls help — but aren't perfect.
  • A Docker backend isolates execution, not every network path.
Enforce permissions in accounts, credentials, tools, filesystem scope, and network policy — not in the prompt.
90 seconds. This is the slide that keeps the pitch honest. Follow org security and procurement requirements before touching work data.

When not to use it — and what it costs.

  • Fixed calculation or threshold alert? A deterministic script wins. The agent can help write it.
  • No productivity percentage claimed here — we haven't measured one.
  • Costs: provider, context, tool use, retries, subagents.
Set a spend limit for a pilot. Inspect actual usage. Stop if repeated attempts aren't producing progress.
75 seconds. For high-stakes actions, keep expert review and existing operational processes.

Try one workflow. Prove the value.

  • Pick a small experiment: a weekly brief, a public-source comparison, docs from a sandbox repo.
  • Time the current process — then time the agent-assisted one, including review and correction.
  • Compare quality, not just speed. Record permissions, data handling, cost.

If it helps, share the reviewed workflow with the club. If it doesn't — keep the simpler approach.

Appendix: from model selection to model routing.

every step on the model someone picked
MODEL ROUTING
frontier only where it matters
FRONTIER MODEL CHEAPER MODEL ONE WEEK OF AGENT WORK
Running every agent step on a frontier model is the expensive default. Routing — frontier only where the task needs it, cheaper models everywhere else — is how a week of agent work stays affordable. Hermes model choice and per-task configuration make this practical. Ties back to the cost slide: set a spend limit, inspect actual usage.
